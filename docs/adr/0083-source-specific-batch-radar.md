# ADR0083 — Source-specific batch annotations stay experimental

27 October 2026. The owner requested implementing the two-item screening plan.
The worker freezes one daily parent source packet, constructs an explicit task
for each item's host-grounded issuer, topic or confirmed event, and splits it
into up to four two-item model calls. The daily parent consumes the existing
date's discovery identity; each child is separately reserved before inference.
Failed/interrupted children are spent. The worker resumes only untouched pairs
and merges results by source and candidate, preserving partial outcomes.

The eight-call validation used two preregistered, disjoint eight-source packets,
with positive, unrelated-issuer and wrong-event controls. Native Qwen decisions
matched the assistant's frozen assessments in 5/8 development and 6/8 held-out
cases: three false matches and two misses overall. All 16 decisions were returned,
but some source-type classifications were also unsupported. These are small,
assistant-reviewed checks, not independent accuracy estimates or forecast proof.

Enable only a labelled research-preview annotation, since the owner requested
useful partial information and the source leads do not depend on the model.
The previous exact broad request remains held. A model decision cannot hide a
source lead, invent issuer links or dates, create a watch or alter a strategy.
Host checks independently retain only supported source fields and withhold an
unsupported model category per item. Full, literal future dates in news excerpts
are shown only as dates mentioned, with event details unconfirmed; confirmed
calendar dates and their 48/24-hour preparation retain their existing clocks.

The new daily budget is one parent with up to four spent child generations,
replacing the previous one-generation daily discovery rather than resetting an
already-used slot. The initial eight validation generations were a distinct
bounded research campaign. Ten-minute idle, the owned Qwen model and digest,
two CPU threads, no GPU and memory limits remain. The paired calendar core,
earlier receipts, operational hold and zero trading weight are unchanged.
An append-only later release decision can disable the preview.
