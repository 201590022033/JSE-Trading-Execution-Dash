# ADR0089 — Source-reviewed outcomes and paired price context

Date: 28 October 2026. Status: accepted for research only.

Individual radar watches can retain an assistant's attributed occurrence
report, including a retrospective report from a source already tied to a
dated child whose event date ended before that child existed. Source
publication, acquisition and receipt clocks remain separate; this does not
create a human verdict, automatic outcome or a successful advance warning.

Add a small adapter over the existing IRESS parser and prospective capture
archive. It records fresh native downloads separately from the existing
OST-primary and longer IRESS histories. A frozen descriptive radar price plan
binds a watch, source review, two aligned IRESS reference captures, their hashes
and actual registration time. Subsequent comparisons consume only the newest
completed row of each later source capture, pairing Sasol and Satrix 40 on the
same observed session and reporting revisions. The first and third paired
observations are not claimed to be complete exchange-session horizons. The
dashboard and CLI read these receipts; reads do not fetch, infer or train.

Reuse of the established `calendar_outcomes` scorer was unsuitable here: it
requires an explicitly frozen numerical calendar expectation and an IRESS
Sasol / OST ETF dataset, while this watch has neither that forecast nor a
current OST login. The separate adapter accepts a useful same-provider IRESS
pair without altering that existing scorer or silently promoting IRESS ETF
data into the OST contract. It is descriptive, not a causal estimate or a
model-skill result, and has no execution weight. Source definitions, the ETF
cross-provider discrepancy, actual event occurrence and session completeness
remain visible limitations. The same original price capture archive is reused;
no parallel provider collector or new model trial is introduced.
