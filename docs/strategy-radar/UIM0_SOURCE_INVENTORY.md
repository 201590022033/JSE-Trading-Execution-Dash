## API and provenance boundaries

`application/strategy_radar/api.py` defines `/api/v1/strategy-radar/` GET endpoints for watches/history, swing, catalog, quotes, intraday, shadow, evidence, monitor and products. POST endpoints handle watch creation/pinning, manual quotes, an explicit ShareData MTN quote, manual intraday input, shadow replay, desk, monitor and trade plan. These methods are not interchangeable: POST may change state, fetch data or trigger model work. Profile identity/version endpoints live in `application/strategy_profiles.py`; backtest reads and explicit ask endpoints live in `application/backtest_lab/blueprint.py`. The main app also exposes market, source, portfolio and system APIs. This is a route-family inventory, not a complete API contract or runtime probe.

Data paths include retained daily history and benchmark histories, manual OST/IRESS imports, manual intraday records, delayed ShareData quote, and source-specific public providers. Preserve source time, receipt time, units and unknown fields. Existing direct Alpha Vantage cash-bar repair and Ollama advisory capability do not establish an Ollama-to-MCP tool workflow; MCP qualification is a later bounded UIM5 task.
