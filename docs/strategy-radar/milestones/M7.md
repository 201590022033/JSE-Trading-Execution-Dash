## Mission

Add a separate, explicitly enabled quiet local worker; do not repurpose the existing dashboard-active calendar/radar clocks. Run during JSE market hours while enabled and PC/session available; poll at a configurable five-minute default subject to actual feed terms. Use the shared watch and intraday evaluation contracts, separate source health from price signal, and retain states and alert history over restarts. ## Checkpoint

Implemented a separate explicitly enabled hidden process in `scripts/strategy_radar_monitor.py`, durable state/leases and event history in `application/strategy_radar/monitor.py`, local dashboard status/control and history, and a Windows notification submission path. Default paused. It reads only retained local bars and makes no provider, model or broker calls. Closed, unreviewed calendar and unknown-source states fail closed; unknown data does not rearm. State and traces persist in SQLite. One-minute to one-hour interval is accepted; UI offers one, five or fifteen minutes. Pause is checked before processing and before atomic event insertion.

Validation: `python -m unittest test_strategy_radar_monitor` passed 9 tests covering holiday/closed/unknown calendar, disabled/empty, source loss/reconnection, deduplication/restart, lease, local-only API, launch/pause and retained bar→trace→dashboard alert history. An isolated temporary-root Windows process acquired a lease, checked an empty watchlist with no dashboard dependency, and exited 0 on pause; launched with CREATE_NO_WINDOW. A Windows test notification returned `SUBMITTED_TO_WINDOWS`, but visible receipt and notification permission were not verified. No actual broker, provider, paid quote or model request was made.

Gaps: no automatically entitled intraday feed is connected; the worker does not fetch data. No Windows startup task is installed; after PC restart or worker failure the user must enable it again, and UI reports enabled but worker not running. Existing running dashboard has not been restarted, so live controls and real dashboard-closed notification behavior remain unverified. The OS submission acknowledgement does not prove display. M6 live validation remains open; do not claim complete runtime acceptance. See [operator guide](../OPERATOR_GUIDE.md).
