## Mission

Run during JSE market hours while enabled and PC/session available; poll at a configurable five-minute default subject to actual feed terms. ## Checkpoint

Implemented a separate explicitly enabled hidden process in `scripts/strategy_radar_monitor.py`, durable state/leases and event history in `application/strategy_radar/monitor.py`, local dashboard status/control and history, and a Windows notification submission path. Default paused. It reads only retained local bars and makes no provider, model or broker calls. Closed, unreviewed calendar and unknown-source states fail closed; unknown data does not rearm. State and traces persist in SQLite. One-minute to one-hour interval is accepted; UI offers one, five or fifteen minutes. Pause is checked before processing and before atomic event insertion.

Validation: `python -m unittest test_strategy_radar_monitor` passed 9 tests covering holiday/closed/unknown calendar, disabled/empty, source loss/reconnection, deduplication/restart, lease, local-only API, launch/pause and retained bar→trace→dashboard alert history. A Windows test notification returned `SUBMITTED_TO_WINDOWS`, but visible receipt and notification permission were not verified. No actual broker, provider, paid quote or model request was made.

Gaps at this 9 November checkpoint: no automatically entitled intraday feed was connected; the worker did not fetch data.
