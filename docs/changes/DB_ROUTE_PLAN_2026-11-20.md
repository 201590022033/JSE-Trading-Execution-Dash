# Proposed single database route — 20 November 2026

Planning only. Execution requires a separate approval for the target, maintenance window, record transfer, configuration changes and any resulting writes. Preserve the current SENS schedule and leave Hermes transfer disabled.

## Current routing

- Dashboard and Research Calendar use the active PostgreSQL connection from the local launcher’s `runtime/local-migration/fresh-20261015/environment.json`, currently `127.0.0.1:55432/trading_local_20261015`.
- `app.py::event_preparation_database_url` accepts `EVENT_PREPARATION_DATABASE_URL` and has a 55432-to-5433 local fallback using `.env.local`. The official 19 November SARB event and its model trace were found on `localhost:5433/trading`.
- `scripts/sens_runtime_bridge.py` asserts the two identities and reads 55432 into 5433. It maintains `runtime/sens-runtime-bridge-cursors.json`. The independent `scripts/macro_calendar_clock.py` and `scripts/macro_expectations.py` use 5433 for calendar work. Macro expectations can read upstream news from 55432. Dashboard Radar SQLite stores sit outside this plan.
- Proposed target is 55432 because the dashboard, upstream SENS and Hermes input records already use it. The SARB record on 5433 and the earlier briefing on 55432 have separate IDs, receipt clocks and provenance. Preserve both.

## Preparation and cutover sequence

1. Export the current scheduled task definitions and record enabled state, scripts, working directories and last status for the SENS roster and calendar workers. Inventory the actual process connections. Read connection identity through separately secured service entries. Never echo the environment files, DSNs or backup contents.
2. Prepare separate auth-restricted backup and staging directories. Back up both PostgreSQL stores using the installed client binaries and private PostgreSQL service aliases `jse55432` and `jse5433` whose host, port and database names match the inventory. Use `pg_dump --dbname=service=jse55432 --format=custom --file=<restricted-dir>/55432.dump` and the equivalent for `jse5433`. Save SHA-256 digests and run `pg_restore --list` on both. Separately copy the two private environment files, bridge cursor if present, deployed code revision, and task definitions to the restricted directory. Record absent files as absent. Rehearse restoration into isolated scratch databases before accepting the backup.
3. Snapshot `paper_records` identities by `kind`, with immutable payload digests and original timestamps. Build a reviewed manifest of missing SARB/calendar, macro attempt/result and dependent receipt records from 5433, including parents and children. Report identical IDs separately from conflicts. Stop on a conflict or unresolved dependency. Audit non-calendar records for other consumers before any retirement decision. Never use a blanket table overwrite.
4. Stage changes in code and provider configuration. Point Event Preparation to the dashboard’s existing 55432 route and remove the local split fallback for this deployment. Make calendar clock and expectation worker accept and validate that same local identity. When both roles use 55432, remove the secondary news connection in the expectation worker and make the SENS bridge exit before any transfer or cursor write when source and destination identities match. Preserve the scheduled upstream SENS tick. Keep the old bridge launcher and cursor for rollback. Test the same-store guard, failure behavior, receipt integrity and Hermes flag with offline fixtures.
5. After separate approval, pause only the affected writers at the agreed cutover point. Take final consistent backups and repeat the manifest. Import only approved missing records to 55432 in an atomic transaction, preserving IDs, data, source and receipt clock. Any conflict rolls back the transaction. Do not execute ingestion, model generation, history reconstruction or Hermes activation as part of the cutover.
6. Apply the staged route and restart only the dashboard. Validate with the checks below before resuming the approved calendar and SENS jobs. Retain 5433 and its private routing files for rollback. Do not retire it on cutover day.

## Read-only verification and rollback

For each private alias, use a read-only transaction with a statement timeout. For example `psql --dbname=service=jse55432 -X -v ON_ERROR_STOP=1 -c "BEGIN READ ONLY; SET LOCAL statement_timeout = 5000; SELECT current_database(), inet_server_port(), current_setting('transaction_read_only'); ROLLBACK;"` in PowerShell. Check the counts and digests against the manifest using the actual schema. Sample Flask TCP peers while opening Research Calendar, Event Preparation and issuer SENS. Confirm all served receipt IDs match 55432, including the official SARB decision and its original metadata. Confirm both SARB IDs remain distinguishable and Hermes opt-in remains off. Check desktop monitor settings and compare the retained alert IDs. A health response alone cannot establish route ownership.

If a route, identity, digest or smoke check fails, pause the affected jobs, restore task definitions and protected/private routing files, switch to the saved revision and restore the prior dashboard route. Check 55432 and 5433 peers and known receipts. Keep the import manifest. If the target transaction committed, reverse only the approved imported IDs when no later records reference them. Obtain separate approval for deletion or a full restore and preserve any post-cutover writes before restoring.
