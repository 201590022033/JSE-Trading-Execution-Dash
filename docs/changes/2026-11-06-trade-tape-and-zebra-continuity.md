# Trade tape and Zebra continuity

The supplied ABSA last-ten table was saved locally as a user-supplied Standard Bank OST observation, with acquisition time, raw structured source bytes and hash, snapshot hash, displayed minute precision, integer cents, whole-share quantities and reported rand values. A later receipt of the same input is another snapshot, not ten new trades: the provider table does not expose transaction IDs. The calculated figures use exact quantity times cents; displayed rand values are retained separately because they are rounded. Do not deduplicate identical prints or infer within-minute order, participant identity, aggressor side, a complete one-minute total or an institutional/retail breakdown.

`scripts/record_trade_tape.py <json>` records additional local snapshots. Backtest Lab reads the saved observations through a no-store read-only endpoint. These data are not automatically collected or used in model fitting or trading. To test future research features, collect a sufficiently frequent, timestamped history with source identifiers and retain matched bid/ask and market context where available. Derive trade-size distributions, volume concentration, activity intensity and price changes from identifiable, time-aligned windows; separately evaluate predictive value against a price-only baseline and control for spread, overlap and time of day.

After public-source refresh and the forward monitor, an expired OST-only dataset no longer prevents a separate bounded BTI/Sasol Zebra Lab replay. The collector still reports the OST issue and will not upload stale broker data. This does not prove a fully successful scheduled run or repair the separate OST export itself. The Backtest Lab status badge checks only for saved filenames rather than loading every report; each selected report is still validated when opened. The target-comparison view was visually confirmed to load and display the Sasol study.
