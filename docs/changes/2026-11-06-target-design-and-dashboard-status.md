# Target design and dashboard status

The target-design study replays fixed 2R and matched historical setup alternatives on the same frozen signal inputs. It separately compares an optional minimum net reward-to-risk target, an optional rejection rule, ATR trailing, EMA21 exit, volume filter and benchmark filter. The net reward threshold is an experimental input, not a trading rule. Per-signal entry, stop, target, estimated costs and reward/risk are retained, as are exit reasons and closed-trade groupings by year and momentum regime. Peer cases use actual prior setups and must have matured by the signal date. Missing peer cases fall back explicitly to fixed 2R. The matched case is a favourable-excursion estimate, not an estimated realised trade profit. The source report retains its Zebra field provenance and timed context; the new report references its content hash. Current classifications, reconstructed availability, assumed costs and unknown actions limit interpretation.

Run a study with `.venv\Scripts\python.exe scripts/run_target_design.py <frozen-momentum-report.json>`. Outputs are content addressed in `runtime/local-backtest/target-design`. The source and code hashes are checked. This does not change the production engine, trade accounts or model budgets.

The daily reminder now checks availability of the Zebra research screen separately from legacy source import receipts and does not infer broker login status. Tab backgrounds indicate the scoped data or service check described inside each tab: green for available/current within that check, amber for partial or unknown freshness, red for unavailable, grey while checking. A green historical backtest or paper account is not a claim of fresh live prices. Refresh view delegates to the existing explicit tab refresh action; check status is read-only. Technical status remains amber until a selected calculation is checked.
