# X1b — legacy news scorer, package 0.2.0

`legacy-news-v1` is a pure, versioned compatibility port of the per-item
deterministic portions of `sentiment_analyzer.py` at
`6a23b027074ba0cf10004f36f3140723e6319d66`. The running analyzer remains unchanged.
This gives research a reusable baseline without importing execution startup,
environment files, credentials, providers, data pipelines or databases.

## Interface

```python
from jse_intelligence_core import score_news, keyword_score, detect_mentions

fixed = score_news("Sasol profits rise")
assert fixed.score == 1.0
assert fixed.provenance.score_origin == "fixed_keyword_heuristic"
assert not fixed.provenance.learned_weights

# Assessment is supplied by the caller, never generated by this function.
assessed = score_news("Synthetic headline", assessment={
    "summary": "Synthetic assessment", "sentiment": "bullish", "score": 0.6,
    "assets": [{"name": "SOL", "direction": 1, "strength": 0.6}],
    "_provider": "fixture", "_model": "synthetic-v1",
})
assert assessed.assets[0].name == "SASOL"
```

`score_news(headline, text="", *, assessment=None, prior_sentiment="neutral")`
returns a frozen `NewsScore` containing summary, sentiment, numeric score,
immutable asset tuple, legacy llm_used flag and frozen `ScoringProvenance`.
`legacy_fields()` returns detached fields directly comparable to AnalyzedItem's
score fields. `to_dict()` adds detached provenance. `keyword_score(text)` and
`detect_mentions(text)` expose the same pure primitives. The scorer attaches no
clock, event/source authority, trade permission, sector validity or calibrated
probability. Caller-owned EvidenceReference records retain those distinctions.

The boundary accepts string headline, optional string/null body, finite
JSON-compatible assessment object/null, and bullish/bearish/neutral prior label.
Invalid container/provider-label types or nonfinite input reject with
ContractError. It accepts supplied data only; no callback or provider client is
accepted. Full provider response validation remains application-owned in
`sentiment_providers.validated_result`; this normalizer is not a replacement.

## Preserved behavior, including known limitations

- Headline and body combine with one space; only lowercasing is applied.
  Matching uses substrings, not token boundaries. Macro mentions precede issuer
  aliases in their original table order. Only aliases, not arbitrary bare ticker
  names, establish deterministic issuer mentions.
- Each matching bullish/bearish lexicon entry counts once regardless of frequency.
  Equal counts produce zero; otherwise `(bull-bear)/(bull+bear)` rounds to two
  decimals using Python's existing rounding. Negation is ignored. Overlapping
  words can count separately. No new tokenizer, financial vocabulary or logic is
  introduced; "no profit" remains positive and substring false positives persist.
- In fallback, a score strictly above 0.1 is bullish, strictly below -0.1 is
  bearish; equality stays neutral. All mentions receive the same direction and
  `min(0.9, abs(score)+0.2)` strength, preserving unrounded binary floating values.
  Neutral detected assets receive 0.2 strength. No mentions still permits a
  nonzero overall score. Primitive mention strengths 0.4/0.5 are overwritten by
  fallback strength, exactly as before.
- None/empty assessment falls back to keywords. A nonempty supplied assessment
  replaces deterministic assets, even if its assets are empty/null/missing.
  Its summary falls back to headline then truncates to 200 characters, sentiment
  lowercases, and score converts/clamps to [-1,1] or becomes zero on conversion
  failure. Missing assessed sentiment can use prior_sentiment. The input's old
  sentiment score is not needed: legacy analyze_item overwrites it on both paths.
- Assessed asset names uppercase/trim and pass through the original ticker map;
  direction int-converts and maps to sign, strength float-converts/clamps to [0,1].
  Bad numeric entries skip. Duplicates and unknown names are retained. Direct
  lenient inputs here characterize the old function's normalization, not the
  stricter transport validator's admission. NaN/Infinity and malformed containers
  are outside this new boundary and reject explicitly rather than becoming scores.

These aliases/mentions are unverified parsing results. They do not pass R12's
separate source citation, issuer applicability, exposure, corroboration or
historical-evidence gates. None of those guards is changed or imported here.

## Origins and provenance

| Field/quantity | Meaning |
| --- | --- |
| Lexicons, aliases, substring rules, thresholds, clamps, rounding | Fixed legacy heuristics, not fitted weights |
| Fallback score/direction/strength | Fixed_keyword_heuristic / fixed_substring_heuristic |
| Supplied summary/sentiment/score/direction/strength | Caller-supplied provider assessment; not observed returns/calibration |
| Assessed alias normalization | Fixed mapping applied to provider-assessed names |
| Provider/model labels and llm_used | Caller assertions / legacy nonempty-result flag; no provider call is proved or performed |
| learned_weights | False: no locally outcome-fitted coefficients are supplied; no claim about an external LLM's training internals |
| Source-priority weights / adaptive-fusion multipliers | Separate application behavior, not part of this scorer |

Provenance includes scorer_version, original source revision/path, immutable input
SHA256, score/asset origins, provider/model labels and learned_weights=false.
The input digest binds sorted, compact ASCII JSON of headline, normalized body
(null becomes empty), complete supplied assessment, and prior_sentiment. No NaN.
It is reproducible, but neither a signature nor proof of source truth. Caller
metadata cannot override scorer version or claim learned coefficients. The
package never reads Git or the original module at runtime.

## Characterization and checks

`fixtures/legacy-news-v1.json` contains 21 fixed synthetic hand-answer vectors:
positive, negative, neutral, missing, rounding, repeated words, ignored negation,
substring/alias overlap, body concatenation, supplied assessment, missing result,
empty assets, numeric normalization, duplicate/unknown assets and exact neutral
thresholds. Expected values were written independently of both implementations.
No real news or private configuration is packaged.

`fixtures/legacy-news-provenance.json` pins the legacy source revision/file hash
and nine relevant constant/function AST hashes. Tests compile only those original
pure functions/records with a rejecting provider stub; no application imports or
startup are needed. Each vector compares both original and shared output to its
fixed expected answer. All lexicon/alias entries additionally check case,
substring and order parity. Isolated import/scoring blocks runtime imports,
network/process/database activity, private file reads and file writes. Existing
X1a schema/identity fixtures continue to pass without changes.

Not extracted: provider JSON validation/transport, prompt construction, scanner
budgets/caches/deduplication, report timestamp/aggregation, source policy weights,
adaptive fusion, or Hermes review/admission logic. Static report audit confirms
macro/ticker averages use direction times strength, macro zeros remain explicit,
ticker headlines retain up to three entries and tickers sort by absolute score;
those application-owned outputs are unchanged. No sector-specific fitting,
negation fix, learned language weights or default change is claimed.

X2 is the next proposed execution card: a file release inbox with validation,
inactive immutable registry and acknowledgements. It requires owner assignment.
Current radar adoption, strategy integration, learned weights and UI remain later.
